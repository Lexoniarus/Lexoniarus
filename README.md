## Engineering approach

- **Understand the domain first:** people, workflows, data quality and failure modes matter as much as technology choices.
- **Keep responsibilities explicit:** separate business rules, state, providers, persistence and UI.
- **Use AI selectively:** language models can interpret ambiguous input; deterministic code should own validation and business decisions.
- **Make change safer:** modular design, reproducible behavior, automated tests and clear implementation-status documentation.
- **Build to learn:** prototypes are useful when their limitations are as visible as their working features.

My current toolbox includes **Python, FastAPI, Flask, Tkinter, SQL, SQLite, MySQL, JavaScript/TypeScript, Astro, GitHub Actions, Docker, ComfyUI and LLM APIs**. Different projects use different subsets; this is not a claim that every tool is used in every application.
